# SPM · 스마트파트너쉽관리

주식회사 투어메이커의 **링크 기반 지급 자료 수집**. 카카오톡·구글폼·싸인오케이 대신 받는 분에게 링크를 보내고, 관리자가 같은 화면에서 확인합니다.

공개 주소는 가이드북과 같이 한 저장소에서 올립니다.

**https://indadady.github.io/spm**

기능이 늘어나도 이 주소를 바꾸지 않습니다. 화면만 경로로 붙입니다.

| 경로 | 용도 |
|---|---|
| `/` | 현황 |
| `/p/…` | 받는 분 입력 (카톡에 넣는 주소) |
| `/payouts/…` | 지급 건 관리 |
| `/ledger` | 원장 |
| `/collect` | 자료함 |
| `/types/…` | 지급 유형 |

김련 박사 자료 링크:

**https://indadady.github.io/spm/p/out-tm-260903-kimryeon/**

## 이 저장소로 두는 이유

가이드북(`260903_Taebaek`, `260908_Osaka`)과 같은 계정·배포 방식입니다. 권한이 익숙하고, `indadady.github.io` 는 이미 파이어베이스 허용 도메인일 가능성이 큽니다. 로컬(`127.0.0.1`)보다 제출이 사무실로 잘 올라갑니다.

앞으로 붙일 만한 것도 여기 한곳에 모읍니다.

- 지급 건마다 원천징수 이전 금액을 직접 넣고, 원천·실지급을 바로 확인
- 강사료 원천 선택 (세금계산서 / 3.3% / 기타 8.8%)
- 유형별 계약 문구
- 행사별 지급 묶음 (태백해설사 심화교육처럼)
- 이체·원천 신고 자료 보관
- 새 지급 유형

직원 급여는 넣지 않습니다. 웹드라마 &lt;영서와 영동&gt; 자문은 대표 개인 수입 참고이며 법인 손금이 아닙니다.

## GitHub에 올리는 방법

1. GitHub에 **`indadady/spm`** 빈 저장소를 만듭니다. (가이드북과 같은 계정)
2. 이 프로젝트 `main`을 그 저장소에 푸시합니다.
3. Settings → Pages → Source를 **GitHub Actions**로 둡니다.
4. `main` 푸시 후 **https://indadady.github.io/spm/** 이 열립니다.
5. 파이어베이스 Authentication 승인 도메인에 `indadady.github.io`가 있는지 확인합니다. 스마트 가이드북 설문이 이미 되고 있으면 되어 있는 경우가 많습니다.

Pages는 정적 파일입니다. 미리 만들어 둔 지급 건(김련)은 주소를 바로 열 수 있습니다. 화면에서 새로 등록한 건은 그 브라우저에서는 보이지만, 다른 사람이 그 주소를 새로고침하면 아직 페이지가 없습니다. 그때는 시드에 넣거나 서버를 붙이면 됩니다.

## 로컬

```bash
npm install
npm run dev
```

`http://localhost:4721` 을 엽니다. 로컬 주소 앞에는 `/spm`이 없습니다.
